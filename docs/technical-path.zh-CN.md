# Drawing Desk 1.0 技术路线与验收说明

[公开工作台](https://rongsenzhang.github.io/drawing-desk/) · [上传或拍照](https://rongsenzhang.github.io/drawing-desk/upload.html) · [英文操作演练](operator-guide.md)

项目围绕报价准备中的一个决定展开：客户询价、工程图纸和引用的规格，是否足以让估价人员开始工作。三套原创的仓储标牌资料分别演示版本冲突、文件一致及规格缺失。招聘人员既可以沿着已有案例走一遍业务流程，也可以上传自己的图片，检验模型读取陌生版面的表现。

## 网页、密钥和图像如何流转

1. 电脑可选取 JPEG、PNG、WebP 或静态 PDF。对于多页 PDF，先选出待检查的那一页，浏览器只将当前页渲染为图片。手机在允许时可调用后置摄像头实时取景，也可以使用系统拍照控件。选取之后先显示预览。
2. 浏览器把选定图像旋转或缩小并重新编码为 JPEG。点击发送才会把这份处理过的图片交给独立服务，服务再调用 OpenAI。用户的 API Key 只在服务端的密钥存储里。原文件、上传的照片及其识别结果不会写入这个公开仓库。
3. 识别接口固定输出图号、版本、材料、表面处理和规格五个字段，支持缺失及不确定状态。本地 OCR 和模型读数分别展示。两个模型给出相同读数仍需要核对原图；定位框是近似位置。
4. 服务通过数据库原子操作限制公共试用量，默认每个客户端每十分钟五次、全站每天一百次。招聘团队无需提供自己的 Key。

## 在企业中继续推进

真实部署需要授权客户资料和独立标注集、估价人员的现行流程和基准时间、受控文档来源、用户身份及审批权限、真实 ERP 接口和现场培训。应按客户及图纸版式分组评测，并分别报告关键字段遗漏、误放行、人工返工和报价准备耗时。当前量化结果只适用于仓库中公开的合成样例。[完整架构和试点路线](architecture.md)

## 1.0 实测数据

三张原始图上，GPT-6.2 Astra 的 15 次字段判断全部符合标注，包括一处缺失规格。14 个有文字的位置框全部包含对应 OCR 文字行的中心。另用不同版式的办公库存卡，从公网手机模拟浏览器的文件选择器实际上传，模型和全图 OCR 各得到 5/5。两组都使用原创合成资料。降采样、遮盖等 18 个受控输入专门测试本地 OCR 和图形识别，本地 OCR 得到 89/90，模型未参加这组受控变形测量。[模型原图结果](../tests/openai-benchmark.json) · [独立上传记录](../tests/openai-upload-e2e.json) · [本地视觉测试](vision.md)

最后又从已发布的手机网页选择一份两页 PDF 的第二页，真实提交该页的 JPEG。模型读出 **CARD-386、F、VINYL、GLOSS、CARD-72**，5/5 符合这一页的标注。[公网选页实测](../tests/openai-pdf-e2e.json)
